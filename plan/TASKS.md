## Standing rules

- Before any `gpu-window` task: `docker stop glm53-flash-2x-rtxpro6000`; after: `docker start` it and confirm `/health`.
- Before any `quiet-host` task: confirm no benchmark is running against the GLM deployment (`uptime` load < 2, `nvidia-smi` utilisation idle); the owner announces the window. Torch benches run in `dsv4-nvfp4:recipe` without `--gpus`.
- Every JSON promoted from `results/` to `evidence/` goes through `scripts/ci.sh`'s identifier scan.
- No pushes from automation. Commits are local until the owner says otherwise.
- **Primary metric (owner decision 2026-09-23, after bug C):** the hybrid is a single-heavy-user machine. Every experiment reports **C1 wall tok/s and TTFT** first; C2 is the realistic multi-user point; C3/C4 are recorded for the cost model, never as the headline. A change that trades C1 for aggregate is not a default. Order of work inside any GPU window: single-user levers first (T3.15 D=5, `KT_CPUINFER` at C1, Engram break time, expert placement), concurrency second.
- **Release gate (E24):** a serving configuration becomes a default only after a ≥ 20K-token mixed C1–C4 distinct-prompt soak with zero NaN/asserts and zero new `Xid` lines in `journalctl -k`. **Batch-consistency gate (added 2026-09-23 after bug C):** every captured decode batch size passes `scripts/verify-batch-consistency.py --same-prompt --concurrency <bs>` (rows of one greedy batch agree with each other and with bs=1) before any C > 1 throughput figure is recorded; a scaling result better than the cost model predicts is treated as a bug signal until that gate passes. `nll-score.py`/`verify.py` run at bs=1 and cannot see a row-2..N defect. No retry-on-NaN or clamping in the serving path; every NaN gets a reproducer and a TROUBLESHOOTING entry.
